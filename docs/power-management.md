# 按需刷新与空闲等待

屏幕保持原亮度和常亮／熄屏设置。按需刷新控制像素传输，不通过熄屏实现。

- 合成画面写入 fbdev 前逐行比较实际 RGB565 像素；相同的行不写 mmap，也不执行无变化的 fsync。此检查同时覆盖 Shell、独立 App、视频叠层和旋转动画，不能只比较 guest draw list（叠层或素材的像素也可能改变）。
- 无动态素材的首页保留独立 RGB565 画面，按 DrawList 的变化区域重绘；删除、移动、半透明控件及背景色变化按原绘制顺序重新合成。动画与页面过渡只修改输出缓冲，不覆盖首页缓存。带图片背景或媒体组件的首页仍按组件顺序进行完整合成，媒体使用组件实际的变换和裁剪区域。
- 首页状态轮询保留组件列表与未变化控件的实例；数值变化只更新对应控件的响应式绘制作用域，不重建整个首页。静态文案跳过变量模板展开。
- CPU 和内存复用 Core 现有资源监视器的两秒样本，通过 D-Bus `GetResources`／`ResourcesChanged` 同步本地缓存；屏幕不再读取 `/proc/stat`。资源通知不触发网络设置读取，样本时间戳不触发重绘，CPU 文本与进度条仍共用五秒显示节奏。
- Pro Desk 的 JD9853 驱动在一次更新开始时取得稳定快照，与上一次成功发送的画面比较；首帧完整发送，随后只发送变化行的连续区间。列地址保留面板的 `0x22` 偏移，行地址必须与 payload 的 offset/len 对应。相同画面不产生 SPI 传输；传输失败后下次完整重绘。
- JD9853 的硬件旋转 0/180 使用行更新；90/270 保留原来的完整窗口传输。Pro 的用户设置 0° 对应物理 270°，由用户态旋转完成，内核面板仍使用硬件 0°，因此正常使用行更新。不要重新采用“固定全屏窗口 + 局部 payload”。
- 旋钮通过阻塞 evdev poll 等待，按住时才设置长按／重复退格的下一个截止时间。旋钮存在不代表正在交互，不能因此让主循环始终以 16 ms 运行。
- 视频、鼠标工作线程在不需要时等待条件变量；切换 App 时立即唤醒。常亮且没有设置任务时，熄屏工作线程也等待通知；设置了熄屏时间时等待实际截止时间。
- 熄屏暂停 guest 脚本、状态轮询、布局、绘制、动画和本地视频／触摸板消费者，只保留唤醒检测和 App 锁超时维护；远程页面单纯查看不会恢复渲染。触摸设备通过阻塞 evdev 就绪通知唤醒；输入、配置或页面事件立即唤醒主线程，锁定超时至多每秒检查一次。输入监听不可用时回退为 32 ms 检测。超时会撤销授权并排队返回首页，无需运行 guest；输入重置空闲计时前也会检查锁定，避免唤醒绕过密码。物理或远程输入唤醒后清理过期动画并重绘当前页，后台设置任务与首次安装完成通知继续处理。其他远程会话的视频消费者不受影响。
- 主循环在交互／动画时保留 16 ms 节奏，屏幕串流显示保留 66 ms 上限；主屏媒体按素材下一帧的时间戳唤醒，不以 60 FPS 重绘低帧率素材。循环和变速参与时间计算，非循环素材结束后停止调度。无触摸设备的空闲状态最多每秒检查一次时钟与目录，配置、旋钮输入会立即唤醒。触摸输入通过独立就绪监听通知主线程，读取一批事件后才重新设防，避免可读 fd 重复唤醒。监听不可用或设置 ONEKVM_SCREEN_TOUCH_POLL 时保留 32 ms 兼容检测。
- 内置 App 可用 `frameAfter` 安排一次延迟重绘（毫秒，最多 60 秒，后一次替换前一次，0 取消），切换 App 时清除；这不会保持 `hot`。串流放大镜用它在无视频新帧时仍于闲置五秒后隐藏，触摸／旋钮重新显示，按住时不隐藏；空闲倒计时不增加逐帧 JS 或像素传输。
- “服务”App 使用独立的服务生命周期通知，并按实际运行状态去重；SSH socket 接受连接时重复上报相同 ActiveState 不触发目录请求，其他 App、Widget 的普通刷新也不触发请求。目录监听仅将祖先路径的创建、删除、移动当成结构变化；祖先 chmod 等元数据通知不触发目录重读，仍保留首次创建、原子替换与目录内部写入的检测。
- H.264 解码复用一块紧凑的原生帧缓冲；VDEC 按通用能力表优先提供 RGB565，其次 NV12/NV21，软件 OpenH264 保持 I420。合成时按最终裁剪和缩放坐标读取 YUV 像素并直接转成 RGB565，RGB565 输出则直接读取，避免先生成整张 RGB888／RGB565 源图。布局、状态、媒体可见性、底色及合成指令的临时缓冲保留容量，内容未变化时复用解析结果；落后超过八个样本时从最近关键帧重新解码并丢弃过期样本。
- Pro 的首页视频解码与远程小屏编码共用系统 OpenH264 加载器和 ABI 检查，使用 OE 编译的 AArch64 NEON 实现。不要重新使用 crate 默认的 ARM 标量解码器。
- 唤醒通知有 generation 计数，等待前必须保留本轮处理前的 generation，防止“处理后、睡眠前”发生的通知丢失。主线程自身处理触摸产生的通知不能绕过 16 ms 帧间隔。

经典表盘的秒标仍每秒变化；概览、数字与翻页时钟只在可见时间变化时刷新。CPU 文字与进度条共用五秒采样，连接状态保留正常两秒刷新。静止的页面应保持零像素传输。此策略不关闭 HDMI 分配器、采集桥或环出，不改变视频消费者的计数。

AX630C 内核另外启用 `CONFIG_NO_HZ_IDLE`，让空闲 CPU 停止周期调度 tick。它不等于 CPU 深度休眠或自动调压，也不会消除外设和后台定时器的必要中断。

修改后要在 Pro 实机检查静态页面、秒标、旋钮短按／长按、旋转、App 切换、视频预览及退出后的 VIN/VENC 休眠。记录相同画面与亮度条件下的 SPI 中断、线程主动上下文切换及片上温度；没有输入功耗和外壳测量时，不给出整机省电或外壳降温结论。NanoKVM PCIe 的屏幕由独立 OLED 服务驱动，不安装 Pro framebuffer 包；NanoKVM PCIe 回归验证登录与视频功能。
