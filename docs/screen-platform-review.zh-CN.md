# 可编程屏幕方案审查

状态：架构建议，尚未实施。本文审查当前主页、组件、SDK、配套插件、存储与开发者模式，
不改变现有接口约定。当前操作方法仍见 [SDK](../packages/screen-sdk/README.zh-CN.md)
和[开发者模式](developer-mode.md)。

## 结论

现有实现已经验证自定义绘制、交互、插件 RPC 和远程检查的可行性，但还不具备完整的
第三方开发流程。核心缺口是程序生命周期、故障边界和事件协议；继续增加调试按钮或
允许绝对路径，不能解决这些问题。

建议保留 PocketJS 绘制与既有扩展包体系，补齐由宿主管理的屏幕程序运行层。
主页、组件与 App 共享程序身份、SDK、构建产物和开发会话，由不同显示角色决定布局与输入。
配套后端按需存在，单纯显示时钟、设备状态和交互布局不应要求开发者编写原生后台程序。

## 当前实现的证据与影响

| 项目 | 源码事实 | 对方案的影响 |
| --- | --- | --- |
| 程序发现 | [apps.rs](../host-linux-fb/src/apps.rs) 的 `contributed_app` 只接受扩展宿主提供的安装根目录，以及根目录内的相对 bundle | 复制到 `/mnt/storage` 不会注册程序；绕过路径校验也无法提供身份、权限和生命周期 |
| 开发流程 | [cli.ts](../packages/screen-sdk/cli.ts) 只有 `init/check/build`；调试目标在 `boot_surface_session` 创建运行实例时出现 | 项目上传、注册、试运行、停止和正式安装之间缺少可用流程；启动前失败的程序也无法成为调试目标 |
| 更新一致性 | SDK 文档要求逐个原子替换 JS、PAK 等资源，再执行 Refresh | 单个文件的原子替换不等于整个版本的原子切换；安装目录也被开发更新直接改写 |
| 主页组合 | [screen_views.rs](../host-linux-fb/src/screen_views.rs) 的 `Views::prepare` 在主页和组件布局之间使用 `if/else if`；Shell 也选择其中一种画面 | 自定义主页与设计器组件目前互斥，没有供主页嵌入已注册组件的公共接口 |
| 事件 | [client.ts](../packages/screen-sdk/src/client.ts) 在 `tick` 比较状态快照；`plugin-state` 只有全局 generation；Refresh 会触发目录重新查询 | 目前是状态变化和失效通知，不能作为带主题、载荷、顺序与丢失检测的业务事件协议；插件之间也会产生无关刷新 |
| 故障隔离 | [main.rs](../host-linux-fb/src/main.rs) 的 `boot_surface_session` 在同一进程创建 UiSurface 和 QuickJS guest；Views 在渲染路径顺序调用它们 | JS 全局与堆彼此独立，但原生崩溃、进程内存耗尽和阻塞仍可能影响系统主页与其他程序 |
| 内存 | [guest.rs](../host-linux-fb/src/guest.rs) 对每个贡献客体限制 32 MiB JS 堆；[服务单元](../packaging/systemd/onekvm-device-screen-display.service) 对整个屏幕组设置 256 MiB 与 `OOMPolicy=kill` | 八个组件的 JS 上限之和已达 256 MiB，尚未计入 Shell、字体、图片和原生内存；不能据此承诺八个组件可同时用满预算 |
| 调度 | Views 在绘制时共享 100 ms 脚本预算，单次最多 50 ms；启动允许每个 guest 执行三秒 | 限制用于终止失控脚本，不是流畅度保证；一个耗尽 50 ms 的组件就会阻塞当前渲染调用。多个冷启动会顺序阻塞；原生资源加载不受 QuickJS 中断器覆盖 |
| 故障恢复 | `screen_views::fail` 以贡献 ID 与版本登记失败，`available` 据此过滤 | 一个实例失败会隔离该贡献的同版本，而非仅隔离该实例；需要明确区分实例故障和版本级熔断 |
| 调试会话 | [devtools.rs](../host-linux-fb/src/devtools.rs) 只有全局租期；状态 GET 续期，关闭面板发送全局 disable | 两个面板不是两个独立会话；一个面板离开会关闭另一个，其他轮询者也可能延长暂停实例的存活时间 |
| SDK 契约 | SDK 方法名接受数字开头、连字符及 64 字符；[扩展宿主路径规则](../../onekvm-extension-host/src/paths.rs) 的 `valid_method_name` 要求小写字母开头、仅小写字母/数字/下划线、最多 63 字符 | 例如 `refresh-now` 可通过 SDK check，却不能作为合法的后端方法；校验必须共用规范 |
| 纯界面包 | [扩展清单校验](../../onekvm-extension-host/src/manifest.rs) 当前要求 entrypoint、命令方法或 environment 类型；SDK 默认模板还依赖 `status` 方法 | 没有明确的一等纯界面扩展类型；不应让仅显示信息的程序携带占位后端，或借用有其他生命周期语义的 environment |

这些是代码与协议边界的结论，不是此前整机失联的根因证明。当前的服务内存上限用于
约束屏幕对整机的影响；不能把它描述成组件之间的进程故障隔离。

## 建议的职责边界

| 层 | 职责 | 约束 |
| --- | --- | --- |
| 系统 Shell / 合成器 | 屏幕、系统导航、输入路由、图层、默认主页、故障回退 | 不执行第三方 JS；自定义主页不能覆盖系统返回与恢复入口 |
| 屏幕程序 runner | 执行 UI、持有实例、生成受限大小的画面、报告故障 | 与 Shell 分进程；无设备文件、任意网络或通用系统控制权限 |
| 扩展宿主 | 包安装、版本、开发注册、程序归属、插件授权和后端调用 | 使用现有扩展身份与事务；不另建屏幕专用包管理器 |
| 配套插件 | 网络、设备操作、业务状态与持久化事件记录 | 可选；权限和资源限制继续由扩展宿主管理 |
| SDK / 开发工具 | UI 组件、状态订阅、事件订阅、RPC、构建、同步与调试 | 开发、正式运行共用契约；开发者模式不自动扩大插件权限 |

建议在 Pro 首先按扩展创建 UI runner，同一扩展的多个组件保留独立 JS 上下文。
这样原生故障影响该扩展的屏幕实例，系统 Shell 与其他扩展继续工作。
这是明确的故障粒度：同一 runner 中的实例不能承诺原生故障互不影响。
每实例单独进程有更细的边界，但要先测量多份引擎和资源的常驻成本，再决定是否提供。

runner 输出优先采用固定上限的共享内存像素表面，由 Shell 负责缩放、裁剪和合成。
每个实例限制尺寸、缓冲区数和更新速率，并通过控制通道提交完整帧序号；Shell 不等待
尚未完成的帧，超时保留上一帧或显示故障状态。像素表面比传递引擎内部对象更容易
划清内存所有权，但仍需实测 IPC、复制、alpha 和帧延迟，不能先承诺现有性能。
输入在宿主完成命中测试、焦点和坐标转换后送入实例，系统手势优先。

## 主页与组件

统一程序生命周期不等于混同显示角色：主页拥有页面布局，组件拥有宿主分配的局部区域，
App 拥有前台页面。SDK 上下文明确角色、实例 ID、局部尺寸、可见性、焦点和配置。

建议允许主页声明由宿主管理的组件槽位：主页决定槽位几何位置，宿主根据布局绑定已注册
组件，继续负责绘制、裁剪、输入和权限。主页不直接导入其他扩展代码，也不获得其插件身份。
不使用槽位的主页仍可自行绘制整页；系统导航始终在宿主层。
组件实例配置属于布局，程序私有持久数据属于扩展数据，二者分别升级和清理。

## 状态、事件与调用

| API 语义 | 适合内容 | 交付规则 |
| --- | --- | --- |
| 状态订阅 | 网络、视频、资源、插件最新状态 | 初始快照加后续更新；允许合并中间值；提供 revision 与重新同步路径 |
| 业务事件订阅 | 操作完成、告警产生、任务进度等有独立含义的消息 | 明确主题、载荷、来源、流 epoch 和序号；队列有界，缺口必须可见 |
| RPC | 查询、刷新、执行动作、保存配置 | 请求/响应 ID、类型化错误、总期限、队列限制和实例销毁语义明确 |

插件通知应由扩展宿主认证来源，再分发给有权限的订阅者。业务状态更新不应依赖调用
ScreenDisplay Refresh，也不应重新扫描包目录。全局设备状态可以继续共用宿主快照。

建议默认提供实时、非持久的事件订阅：先建立有界缓冲订阅，再取得带序号的快照，
交付快照之后的消息，避免先读后订阅的窗口丢失；断线、隐藏期间溢出或后端重启时
报告 gap/reset。需要逐条恢复的事件，由插件保存日志，提供按 cursor 补读的方法。
没有持久化日志和确认协议时，不承诺所有事件必达或 exactly-once。
隐藏与息屏可以停止 UI 调度，业务任务继续由后端完成，不能依赖 UI 每帧运行。

RPC 默认绑定所属插件；调用其他插件时，必须有单独声明和授权的服务绑定。
每次调用由宿主校验身份、方法与当前启用状态，不能相信页面提交的插件 ID。
配置与密钥仍由插件 schema 和宿主处理。超时只表示调用方不再等结果，已执行写操作
可能成功；写操作不得自动重试，确有需要时由后端支持幂等键。

SDK、CLI 与扩展宿主共用方法名和载荷规范。SDK 发布前还需固定事件类型、错误码、
能力协商、可选后端语义，以及 home/widget/app 对公共 SDK 的支持范围。

## 内存、调度与恢复

1. 分开限制 Shell 与不受信任的 UI runner。runner 应使用独立 systemd 服务与 cgroup，
   放在受限的 guests slice 中；不能全部留在会被 `OOMPolicy=kill` 一起终止的屏幕服务组里。
2. 先测量 Shell 基线、单 runner、同扩展多实例和跨扩展多实例，再分配总预算。计入 JS、
   解码资源、原生节点、共享表面、文件缓存和进程开销。原有 192/256 MiB 可保留作迁移期
   保护，拆分后的上限必须重新核算，不能给每个 runner 都分配 256 MiB。
3. 开始运行前做资源准入：限制 bundle、解码尺寸、字体、原生节点、实例数和并发启动数；
   超额拒绝新增实例并说明原因，避免靠整组 OOM 发现超额。
4. 冷启动、字体/图片解码、布局和光栅化不在 Shell 的输入循环等待。JS 执行预算与画面
   更新调度分别定义；卡住的 runner 由宿主超时终止，系统导航保持响应。
5. 实例错误、runner 崩溃与构建版本持续失败分别记录。重试有上限与退避；反复失败后
   恢复默认主页。开发态允许显式重试，正式开机不能无限重新进入同一故障程序。

## `/mnt/storage` 与开发者模式

程序可以放在存储分区，但路径只负责存放文件。开发注册必须同时确定程序身份、
构建版本、运行权限、配套插件和恢复方式。
`/data` 位于根 overlay，`/mnt/storage` 是独立挂载。
当前正式扩展根为 `/data/onekvm/apps/<id>/<version>`。

建议先增加受认证的开发注册与同步流程，存储位置示意如下；这些目录目前不会自动加载：

| 内容 | 建议位置 | 管理方式 |
| --- | --- | --- |
| 源码项目 | 开发电脑，或 `/mnt/storage/onekvm/dev/projects/<project-id>/` | 开发者编辑；运行时不直接执行正在修改的目录 |
| 开发构建 | `/mnt/storage/onekvm/dev/builds/<project-id>/<build-id>/` | 校验后不可变；限制文件总量、解压大小与路径；显式注册，不递归自动执行 |
| 开发会话 | `/run/onekvm/…` | 记录登录主体、构建 ID、运行实例、授权和租期；到期停止并恢复之前主页 |
| 正式包与数据 | 当前由扩展宿主管理的安装根及 app-data | 若需迁移到存储分区，由扩展宿主连同升级、回退、卸载、空间管理统一处理 |

上传先进入 staging，校验整份清单与文件哈希，生成独立 build ID，再切换活动引用。
构建失败或新实例未启动成功时保留上一版本；不逐个覆盖当前正在使用的资源。
单靠路径检查或只读映射不足以解决更新者原地修改 PAK 的问题，需要受管理的不可变快照。
试运行改变的是会话中的显示选择，默认不改正式布局，也不写开机自启。

下面表示建议提供的工具流程，当前 CLI 尚不支持 `dev`、`stop` 或 `pack`：

```text
init → 本地构建/类型检查 → dev（认证、同步、注册、试运行）
     → 检查组件/日志/真实屏幕 → 修改后同步整版 → stop（恢复原主页）
     → pack → 按既有扩展安装流程正式安装
```

开发会话使用独立控制租约；观察画面的客户端不能为别人的暂停状态续期，关闭观察者
也不能禁用其他会话。每个目标只允许一个控制者，其他客户端可观察；控制者断线后
恢复暂停实例并清理高亮，开发试运行到期后停止。开机仍默认关闭开发模式。
调试面板要显示构建/启动失败，即便程序尚未成为运行目标。

工具链应提供可独立安装、固定 PocketJS 版本和字体资源的 SDK，而不是要求开发者
先准备整个固件工作区。开发页面只需要主机工具编译为 JS/PAK；正式发布可继续由 OE
生成原有扩展 IPK，两者使用相同 manifest 与能力校验。
当前组件树、控制台、全局 eval 和逐帧可保留；源码断点与 CDP 是另外的引擎能力，
不能通过增加 source map 或“开发者模式”开关就宣称支持。

## 引擎选择与实施顺序

本轮没有证据表明必须更换 PocketJS；已经可用的绘制、输入和组件应作为候选实现保留。
它也不是浏览器 Vue：缺少 DOM、浏览器网络接口与标准浏览器调试器，动态文字还有字形
准备成本。独立 SDK 必须明确这些约束。若产品要求完整 Web 生态、源码断点或任意动态
字体，应另做 WebView/QML 等候选的原型，实测启动、常驻内存、功耗和调试能力；本轮未做
候选引擎性能对比，不据此承诺某个引擎更轻或更快。

| 顺序 | 交付 | 验收条件 |
| --- | --- | --- |
| 1 | 程序身份、纯 UI 扩展语义、SDK 协议和错误模型 | 无后端的设备状态主页可安装；方法名在 CLI、SDK、宿主校验一致；已有扩展兼容 |
| 2 | 独立 runner、资源准入和故障回退 | JS 死循环、原生异常、内存超限、慢启动只影响规定的故障范围；系统导航、Core 与 watchdog 持续工作 |
| 3 | 事件与插件服务绑定 | 订阅初始化无竞态；来源不可伪造；突发、隐藏/恢复、重连和队列溢出都有明确结果 |
| 4 | 开发同步与版本事务 | `/mnt/storage` 构建可注册运行；断传、坏包、启动失败保留旧版；会话停止恢复原主页 |
| 5 | 主页组件槽位、独立 SDK 与调试体验 | 自定义主页可组合组件；离开开发会话恢复；多客户端不互相关闭；新开发者无需固件工作区完成首个项目 |

每项需要在 支持屏幕显示的机型上验证实际 framebuffer、触摸/旋钮、后台与息屏、失控恢复和持久化。
涉及共享扩展宿主或 Core 的修改，还需验证扩展、登录和视频功能。
